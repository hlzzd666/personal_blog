# 模块讨论清单

具体业务模块在实现前，先确认以下内容：

## 首页

- 首屏要表达的个人定位和核心行动
- 航海日志视觉元素的使用范围
- 是否需要精选文章、航海地图、时间线、订阅入口
- PC、平板、手机端的优先级

## 文章

- 文章列表筛选：标签、分类、搜索、分页
- 文章详情：目录、代码高亮、图片、阅读量、分享
- 不设置草稿和已发布状态，文章写入后直接进入博客内容
- URL、SEO、Markdown 编辑方式
- 后台维护标题、摘要、封面、转载标记、作者、来源链接、发布时间、更新时间、浏览量、点赞数、标签和分类
- Markdown 内容使用可预览编辑器，发布时间和更新时间允许管理员选择日期时间格式
- 前台按归档、标签、分类组织文章；归档以发表时间整合为一条时间线，详情首次加载增加一次浏览量。公开点赞按文章和匿名访客标识做唯一记录，详情回显当前访客的点赞状态，重复请求不重复累加
- 全站导航提供文章检索入口：关键词匹配标题、摘要与 Markdown 正文；结果展示文章分类、发表时间和摘要，点击后进入文章详情
- 管理接口沿用现有后台鉴权边界；当前项目登录态仍为前端本地会话，生产部署前需替换为服务端认证

## 关于自己

- 导航与页面统一命名为“关于我”，使用独立前台路由 `/about`
- 公开展示个人介绍、状态、头像、工作经历、项目经历、技术栈、兴趣、联系方式、社交链接和关于本站
- 工作经历、项目经历、技术栈与社交链接均支持后台增删、排序和编辑；技术栈每项维护名称与上传图标，头像与技术图标沿用媒体上传能力
- 关于我资料采用单例数据模型，通过 `/api/v1/about-profile` 读写，公开接口只返回页面实际展示字段
- 城市与经纬度在关于我后台维护；前台地图使用高德地图 JS API，Key 与安全密钥由前台环境变量提供，不写入业务数据或仓库
- 当前管理端登录仍为本地会话，关于我写接口沿用既有管理接口边界；生产部署前统一补充服务端鉴权

## 访客定位展示

- 首页信息舱展示访问者 IP、城市、地区和国家，不写入数据库或业务日志
- 后端调用第三方 IP 地理定位服务，需在站点隐私说明中告知访客
- 仅配置为可信的反向代理可传递 `X-Forwarded-For`，避免伪造来源地址
- 站长地址名称与详细经纬度仅由后台维护；后端计算访客与站长的直线距离，前台不返回坐标原值

## 管理后台

- 登录方式、管理员角色和权限
- 文章编辑器、预览和内容库维护；文章写入后直接进入归档、标签和分类体系
- 媒体资源管理
- 操作日志和数据统计

## 数据与非功能

- MySQL 版本、部署方式和备份策略
- 是否需要 Redis、对象存储、邮件服务
- 是否需要国际化、暗色模式、评论和 RSS
